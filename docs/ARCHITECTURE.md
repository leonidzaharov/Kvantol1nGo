# Архитектура «Кванториума»

Документ описывает состояние системы на 28 июля 2026 года. Исторические схемы из
`docs/archive/` не следует использовать как инструкцию.

## Границы системы

Приложение — единый Next.js-монолит. Страницы, Server Actions, Route Handlers,
авторизация и доступ к данным находятся в одном репозитории. Отдельного REST API
для интерфейса нет.

```text
Браузер
  ├─ Server Components → HTML
  ├─ Client Components → интерактивность урока
  ├─ Server Actions → мутации и учебная телеметрия
  └─ Route Handler → снимок живого дашборда
          │
Next.js App Router + Auth.js + proxy.ts
          │
Prisma → PostgreSQL / Supabase
          ├─ Supabase Storage (изображения)
          └─ Sentry / Vercel telemetry
```

Python и JavaScript ученика не выполняются на сервере. Python работает через
Pyodide, JavaScript — в Web Worker с ограничением времени.

| Путь | Ответственность |

| `src/app/(main)/` | защищённый ученический и административный интерфейс |
| `src/app/lesson/[id]/` | проигрыватель урока и кодовые задания |
| `src/lib/actions/` | Server Actions и транзакционные мутации |

| `prisma/migrations/` | история схемы PostgreSQL |
| `prisma/seed-lessons/` | переносимый стартовый каталог уроков |
| `scripts/` | эксплуатационные команды |
| `e2e/` | изолированные Playwright-сценарии |

## Пользовательские маршруты

| Маршрут | Назначение | Доступ |
| --- | --- | --- |
| `/` | выбор направления, группы, профиля и вход | публичный |
| `/mentor` | вход наставника по имени и длинному PIN | публичный, не в навигации |
| `/privacy` | политика конфиденциальности | публичный |
| `/learn` | активный курс и карта уроков | авторизованный |
| `/courses` | выбор доступного курса | авторизованный |
| `/lesson/[id]` | теория, вопросы и кодовые задания | авторизованный, с проверкой направления |
| `/lesson/[id]/preview` | безопасный предпросмотр без прогресса | только наставник |
| `/leaderboard` | рейтинг по XP | авторизованный |
| `/interesting` | дополнительные материалы | авторизованный |
| `/works` | назначенные ручные работы и история ответов | авторизованный ученик |
| `/works/[id]` | отправка текста, ссылки или кода | назначенный ученик либо владелец истории |
| `/achievements` | прогресс достижений и витрина | авторизованный |
| `/profile` | собственный профиль | авторизованный |
| `/profile/[id]` | публичный внутри платформы профиль | авторизованный |

Админка начинается с `/admin` и содержит разделы `lessons`, `categories`,
`groups`, `achievements`, `resources`, `review-assignments` и `activity`. Каждая страница повторно
проверяет `isAdmin` в БД и для обычного ученика отвечает 404.

`/admin/activity` — кабинет текущего очного занятия. Наставник выбирает группу и
опубликованный урок, запускает сессию и видит состояние учеников с обновлением
раз в три секунды. Если ребёнок открыл урок раньше, его шаги временно пишутся в
скрытый предзапуск и становятся видны при запуске наставником этого же урока.

Route Handlers:

- `/api/auth/[...nextauth]` — Auth.js;
- `/api/admin/upload-image` — административная загрузка в Storage;
- `/api/admin/class-sessions/[id]` — защищённый снимок живого занятия без
  кеширования;
- `/api/health` — проверка доступности приложения и БД;
- `/api/orphan-signout` — очистка сессии удалённого пользователя.

## Модель данных

Основные домены:

1. `User`, `Group`, `LoginAttempt` — учётные записи, направления и защита входа.
2. `Category`, `Lesson`, `CategoryGroupAssignment`,
   `LessonGroupAssignment`, `UserLessonProgress` — программа, ручная публикация,
   аудитория и прогресс.
3. `ClassSession`, `SessionStudentProgress`, `SessionQuestionProgress` —
   отдельное текущее состояние очного занятия и счётчики ошибок по задачам.
4. `Achievement`, `UserAchievement` — настраиваемые достижения.
5. `Resource`, `ResourceGroupAssignment`, `UserResource` — публикация,
   групповая аудитория дополнительных материалов и разовые награды.
6. `ReviewAssignment`, `ReviewAssignmentGroup`, `ReviewAssignmentUser`,
   `ReviewSubmission`, `ReviewSubmissionVersion` — независимые ручные работы,
   текущий статус и неизменяемая история проверок.

Пара `(userId, lessonId)` уникальна, поэтому повторное прохождение не создаёт
вторую запись прогресса. Начисление наград выполняется транзакционно и
идемпотентно.

Сессионная аналитика не хранит ответы или исходный код ребёнка. Постоянный
`UserLessonProgress` отвечает за XP и завершение урока, а `ClassSession` — только
за происходящее на конкретном занятии. Поэтому повтор старого урока не
смешивается с новой очной сессией.

`ClassSession.activatedAt = null` обозначает скрытый предзапуск: он не попадает в
список активных занятий и API дашборда. Первый heartbeat ученика создаёт такой
буфер под транзакционной блокировкой группы; кнопка наставника атомарно активирует его,
не теряя уже записанные позиции и ошибки. Предзапуски старше четырёх часов
закрываются, чтобы данные прошлого занятия не смешивались с текущим. Активированное
занятие также лениво закрывается через четыре часа при следующем обращении дашборда
или ученика. Перерывы и отсутствие действий внутри этого окна ничего не закрывают;
запуск нового урока группы завершает её прежнее занятие.

Ручная работа не имеет внешних ключей на `Category`, `Lesson`, `ClassSession`
или `UserLessonProgress`. Состояние «не отправлено» не хранится: оно вычисляется
как назначенная работа без `ReviewSubmission`. Каждая повторная отправка
создаёт новую `ReviewSubmissionVersion`; код хранится как текст, подсвечивается
в браузере и никогда не выполняется.

## Журнал действий наставника

`AdminAuditLog` хранит только критические административные события: создание,
удаление, публикацию, изменение аудитории, сброс PIN, выдачу достижения,
решение по ручной работе и управление очной сессией. Запись создаётся в одной
транзакции с изменением данных. Содержимое уроков и работ, комментарии, ответы,
код и PIN в журнал не копируются. `/admin/audit` показывает последние 100 событий,
а записи старше 180 дней удаляются при следующем журналируемом действии.

## Авторизация и права

- Ученик выбирает существующий профиль и вводит четырёхзначный PIN.
- `User.name` — публичный ник, а `User.mentorLabel` — приватная подпись, доступная
  только в интерфейсах наставника. До первого подтверждения профиля ученик
  перенаправляется на `/profile-setup`.
- PIN хранится только как bcrypt-хеш; исходный PIN в БД не записывается.
  Ученик сначала выбирает профиль, поэтому одинаковые PIN разрешены и проверяются
  в связке с идентификатором выбранного пользователя. Прежний HMAC-отпечаток
  больше не рассчитывается и оставлен в схеме только на переходный деплой.
- Наставник входит через `/mentor` по имени и PIN длиной 8–10 цифр.
- Сессия JWT живёт до 8 часов и содержит только идентификатор пользователя.
- Актуальный административный флаг всегда читается из БД.
- `src/proxy.ts` защищает маршруты и создаёт nonce для строгого CSP.
- Server Actions используют `requireUser()` или `requireAdmin()` и Zod.
- Публикация и назначение группе повторно проверяются при открытии курса,
  урока, карточки «Интересного» и ручной работы, поэтому прямой URL или
  поддельный запрос не обходят ограничение.
- История собственной ручной работы остаётся доступной после архивации, но
  новую версию можно отправить только в опубликованную и всё ещё назначенную
  работу.

## Рендеринг и данные

Server Components используются по умолчанию и читают Prisma напрямую. Client
Components применяются только там, где нужны состояние браузера, редактор,
анимация или runner. Мутации интерфейса проходят через Server Actions, внешние
HTTP-входы — через Route Handlers.

Единый Prisma-клиент измеряет длительность запросов. Запросы медленнее 500 мс
(или порога `DB_SLOW_QUERY_MS`) отмечаются в серверном логе префиксом
`[db:slow]`. В запись попадают только длительность, операция и названия таблиц;
SQL-параметры и данные учеников не журналируются.

Проект работает на Next.js 16:

- `params`, `searchParams`, `cookies()` и `headers()` считаются асинхронными;
- вместо старого `middleware.ts` используется `src/proxy.ts`;
- API из Pages Router в проект не добавляются;
- документация установленной версии лежит в `node_modules/next/dist/docs/`.

## Проверки качества

- Vitest тестирует чистую бизнес-логику и валидацию; отдельная конфигурация
  `vitest.integration.config.ts` проверяет Server Actions на временной схеме
  PostgreSQL `integration`.
- Playwright поднимает отдельную PostgreSQL-схему и проверяет путь ученика,
  повторное прохождение, витрину достижения, живой кабинет, групповую карточку
  задания со звёздочкой, ролевые границы, административный CRUD и полный цикл
  ручной проверки с повторной отправкой. `@axe-core/playwright` блокирует
  serious/critical нарушения доступности на ключевых экранах ученика и
  наставника.
- GitHub и Gitea CI выполняют `npm ci`, `prisma generate`, lint, unit- и
  PostgreSQL integration-тесты, TypeScript, production-сборку, синтетическую
  проверку восстановления и Playwright.
- Локальный pre-push выполняет lint и `tsc --noEmit`.

Асинхронные Server Components целесообразно проверять E2E-тестами: именно этот
подход рекомендует локальная документация Next.js 16.

## Правила изменения архитектуры

1. Сначала обновить Prisma schema и создать миграцию, затем менять код.
2. Не принимать `userId` от клиента для операций текущего пользователя.
3. Денежные награды и прогресс изменять в транзакции.
4. Любое действие наставника защищать серверным guard.
5. Не импортировать браузерные библиотеки в Server Components.
6. Новый тип задания сначала добавить в валидатор `lesson-content.ts`.
7. При значимом архитектурном решении добавить ADR в `docs/decisions/`.
