# Учебная практика: подключение и сопровождение

Практика подключена к существующим страницам урока и редактору. Классические уроки используют QuestRunner, новый явно заданный формат practice-v1 использует LessonPractice и PracticeRunner. Новых зависимостей, таблиц и колонок для этого этапа нет.

Формат для авторов и генераторов: [PRACTICE_FORMAT.md](PRACTICE_FORMAT.md). Инструкция команде и порядок проверки: [PRACTICE_HANDOFF.md](PRACTICE_HANDOFF.md). Решения и публикация готовых занятий остаются вне репозитория приложения.

## Данные и проверка

Публичный PracticeItem содержит ID пункта, короткую вводную и 2-3 варианта. Правильные ответы и объяснения не входят в начальные данные ученика. После попытки сервер возвращает PracticeCheckResult с результатом и разбором. Для match возвращаются правильные связи.

PracticeRunner получает функцию checkAnswer(attempt, signal). Обёртка LessonPractice добавляет lessonId, revision и section. AbortSignal остаётся в браузере; он не передаётся параметром Server Action. Запоздавший ответ после закрытия сессии игнорируется локально, уже выполненная серверная операция не отменяется.

sessionKey связывает локальное состояние с учеником, уроком и ревизией. Смена ключа сбрасывает очередь и черновик. Подтверждённые основные решения восстанавливаются по точному набору answeredCore, а не по предполагаемому префиксу answeredCount.

## Учебная последовательность

1. Короткая теория из MD, если она есть, и переход к практике.
2. Самостоятельная попытка. Проверка запускается только по кнопке.
3. Разбор с правильным ответом и объяснением после верного и неверного ответа.
4. Неверный пункт возвращается после двух других с другим вариантом. Если других пунктов нет, новый вариант появляется сразу.
5. Просмотр ответа не считается решением. Очередь содержит каждый нерешённый пункт один раз.
6. После всей обязательной части ученик явно подтверждает завершение. Сервер заново проверяет точное покрытие и выдаёт существующую награду первого прохождения.
7. Бонусы доступны отдельно после основного финиша, необязательны и не дают дополнительной выплаты. Повтор завершённого урока даёт 0 монет.

Сбой проверки сохраняет ввод на текущем экране. Сбой подтверждения финиша позволяет повторить подтверждение без повторного решения урока. Предпросмотр требует прав наставника и не создаёт ученический прогресс/монеты.

## Производительность и ограничения

Движение указателя меняет только временную SVG-линию через ref/requestAnimationFrame. ResizeObserver обновляет координаты карточек; кадры и наблюдатель очищаются при размонтировании. Карточки перемешиваются независимо один раз со стабильным seed, одинаковым при гидратации.

Сопоставление не создаёт запросов до проверки и не загружает Pyodide. Новый runner не добавляет heartbeat или WebSocket. Существующий сбор сессионной статистики в общей системе не удалён: отметки ответов могут создавать скрытую сессию, но положение до первой попытки в новом runner автоматически не обновляется.

После перезагрузки сохраняются подтверждённые основные решения, но точный порядок повторов, выбранный вариант, несохранённый ввод и бонусная очередь не восстанавливаются. Кодовые задачи остаются в классическом формате. Развёрнутое рассуждение не оценивается сравнением строки; для него есть ручные работы.

Для уже опубликованной практики или практики с прогрессом содержимое блокируется. Метаданные и ручная сумма награды редактируются. Для другого набора вопросов создаётся отдельный урок. Удаление контента из старой редакции не должно молча обнулять прогресс.

## Проверка

Основные команды: npm test, npm run lint, npx tsc --noEmit и npm run build. Тесты схем, импорта, очереди, страниц и серверных действий используют синтетические данные и подменённую БД. Реальную конкурентность PostgreSQL, нагрузку и весь маршрут входа нужно проверять на отдельной тестовой базе перед публикацией.
