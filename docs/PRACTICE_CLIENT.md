# Учебная практика: подключение и сопровождение

Практика подключена к существующим страницам урока и редактору. Классические уроки используют QuestRunner, новый явно заданный формат practice-v1 использует LessonPractice и PracticeRunner. Новых зависимостей, таблиц и колонок для этого этапа нет.

Формат для авторов и генераторов: [PRACTICE_FORMAT.md](PRACTICE_FORMAT.md). Инструкция команде и порядок проверки: [PRACTICE_HANDOFF.md](PRACTICE_HANDOFF.md). Решения и публикация готовых занятий остаются вне репозитория приложения.

## Данные и проверка

Публичный PracticeItem содержит ID пункта, короткую вводную и 2-3 варианта. Правильные ответы и объяснения не входят в начальные данные ученика. После попытки сервер возвращает PracticeCheckResult с результатом и разбором. Для match возвращаются правильные связи. Для code публичны только language и starterCode в дополнение к id/type/prompt; эталонный код, explanation и expectedOutput приходят после проверки.

Код выполняется через общий runCode. Запрос проверки code содержит executionOk и output до 10000 символов, без исходника. Сервер требует успешное выполнение и сравнивает вывод существующим outputsMatch с приватным эталоном. Клиент способен подменить результат выполнения, поэтому этот режим не является доверенным экзаменационным выполнением. Ошибка самой программы получает учебный разбор; сбой загрузки движка или проверки сохраняет ввод без ложной попытки.

PracticeRunner получает функцию checkAnswer(attempt, signal). Обёртка LessonPractice добавляет lessonId, revision и section. AbortSignal остаётся в браузере; он не передаётся параметром Server Action. Запоздавший ответ после закрытия сессии игнорируется локально, уже выполненная серверная операция не отменяется.

sessionKey связывает локальное состояние с учеником, уроком и ревизией. Смена ключа сбрасывает очередь и черновик. Подтверждённые основные решения восстанавливаются по точному набору answeredCore, а не по предполагаемому префиксу answeredCount.

## Учебная последовательность

1. Короткая теория из MD, если она есть, и переход к практике.
2. Самостоятельная попытка. Проверка запускается только по кнопке.
3. Разбор с правильным ответом и объяснением после верного и неверного ответа.
4. Неверный пункт возвращается после двух других с другим вариантом. Если других пунктов нет, новый вариант появляется сразу.
5. Просмотр ответа не считается решением. Очередь содержит каждый нерешённый пункт один раз.
6. После всей обязательной части ученик явно подтверждает завершение. Сервер заново проверяет точное покрытие и выдаёт существующую награду первого прохождения.
7. Бонусы доступны отдельно после основного финиша, необязательны и не дают дополнительной выплаты. Повтор завершённого урока даёт 0 монет.

Сбой проверки сохраняет ввод на текущем экране. Сбой подтверждения финиша позволяет повторить подтверждение без повторного решения урока. Предпросмотр требует прав наставника и не создаёт ученический прогресс/монеты.

## Производительность и ограничения

Движение указателя меняет только временную SVG-линию через ref/requestAnimationFrame. ResizeObserver обновляет координаты карточек; кадры и наблюдатель очищаются при размонтировании. Карточки перемешиваются независимо один раз со стабильным seed, одинаковым при гидратации.

Сопоставление не создаёт запросов до проверки и не загружает Pyodide. Новый runner не добавляет heartbeat или WebSocket. Существующий сбор сессионной статистики в общей системе не удалён: отметки ответов могут создавать скрытую сессию, но положение до первой попытки в новом runner автоматически не обновляется.

После перезагрузки сохраняются подтверждённые основные решения, но точный порядок повторов, выбранный вариант, несохранённый ввод и бонусная очередь не восстанавливаются. Кодовые задачи поддержаны и в classic, и в practice-v1 через общий runCode. Развёрнутое рассуждение не оценивается сравнением строки; для него есть ручные работы.

Python загружается со своего сайта в Worker при первом запуске или прогреве. Загрузка ограничена 45 секундами, исполнение 3 секундами, общий stdout/stderr 10000 символами. Выполнения идут последовательно и получают новые globals. Тайм-аут и переполнение вывода завершают Worker; следующий запуск создаёт новый. Отдельный CSP для `/pyodide-worker.js` разрешает скрипты и соединения только с этим сайтом. Worker сохраняет отзывчивость страницы при бесконечном Python-цикле, но не задаёт измеренный предел памяти процесса браузера.

Для уже опубликованной практики или практики с прогрессом содержимое блокируется. Метаданные и ручная сумма награды редактируются. Для другого набора вопросов создаётся отдельный урок. Удаление контента из старой редакции не должно молча обнулять прогресс.

## Проверка

Основные команды: npm test, npm run lint, npx tsc --noEmit и npm run build. Unit-тесты схем, импорта, очереди, страниц и серверных действий используют синтетические данные и подменённую БД. Интеграционные тесты используют выделенную схему локальной PostgreSQL, а e2e/practice-code.spec.ts проверяет реальный браузерный Python и сценарии повторения/восстановления. Наличие теста не означает подтверждённый успешный прогон текущей редакции. Нагрузку и весь маршрут входа проверять на отдельной тестовой базе перед публикацией.

## Вход через «Интересное»

В форме материала есть виртуальный тип «Интерактивная практика». В существующей БД он хранится как Resource.type=article, url=`/lesson/id`, coinReward=0. Миграции, нового enum и копии вопросов нет. Публичная карточка открывает тот же Lesson, берёт его награду и читает завершение из UserLessonProgress. Метаданные связанных уроков и прогресс загружаются общими выборками, без запроса для каждой карточки.

При сохранении проверяется существование и формат связанного Lesson. Публикация дополнительно требует публикации урока/курса и доступа назначенных групп. Ученик видит карточку только при доступе к связанному уроку. У карточки практики нет действия «Изучил»; прямой studyResource отклоняется на сервере до отметки и выплаты. Классификация карточки согласуется блокировками с редактированием Resource. Начисление остаётся только в completeLesson: несколько карточек одного Lesson не создают дополнительные награды.
