# Формат практики и импорт Markdown

Документ для команды редактора и авторов генераторов. Готовые занятия, JSON уроков и изображения остаются вне репозитория приложения. Примеры ниже синтетические и описывают контракт.

## Совместимость

Классический Lesson.content остаётся объектом без поля format: theory, questions, bonusQuestions. Существующие вопросы choice, text и code, отсутствие type у старого choice, псевдонимы question/text для prompt и настройки Python по умолчанию сохраняются.

Новый формат явно помечается `format: "practice-v1"`. Нельзя передавать его классическому парсеру с отбрасыванием неизвестных полей. Неизвестная версия или повреждённые данные возвращают ошибку, а не пустой завершённый урок. Кодовые задания в practice-v1 пока запрещены; для них продолжает работать классический формат.

Сервер и редактор используют одни схемы из `src/lib/practice-content.ts`. Общий разбор документа находится в `src/lib/lesson-document.ts`. Объяснения и эталонные ответы хранятся в документе наставника и не входят в начальные данные ученика.

## Структура practice-v1

```ts
type StoredPracticeContent = {
  format: "practice-v1";
  theory: string; // По умолчанию пустая строка.
  questions: StoredPracticeItem[];
  bonusQuestions: StoredPracticeItem[]; // По умолчанию [].
};

type StoredPracticeItem = {
  id: string;
  intro?: string;
  variants: StoredPracticeVariant[];
};
```

Основных пунктов 1..50, бонусных 0..20. На каждый пункт нужны 2..3 равнозначных варианта одного навыка. ID пункта уникален среди основных и бонусных пунктов; ID варианта уникален внутри пункта. ID содержит 1..48 символов после обрезки пробелов. intro содержит до 800 символов обычного текста.

У каждого варианта обязательны id, type, prompt до 3000 символов и explanation до 1000 символов. Объяснение непустое. Неизвестные поля нового формата отклоняются, чтобы опечатка не уничтожила часть данных при сохранении.

| type | Дополнительные поля | Проверка |
| --- | --- | --- |
| choice | options: 2..8 непустых строк до 300 символов; correctIndex: целый индекс с нуля | Сравнение выбранного индекса |
| text | correctAnswer: непустая строка до 1000 символов | Существующий textAnswersMatch: регистр, пробелы, конечная пунктуация |
| match | left/right: 2..8 карточек {id,label}; correctPairs: {leftId,rightId}[] | Полный набор правильных пар, порядок массива не важен |

Для match длины колонок совпадают. label содержит 1..160 символов. ID всех карточек обеих колонок уникальны и независимы от правильного ответа. correctPairs покрывает каждую карточку ровно один раз; неизвестные ID, повторные связи и неполный эталон запрещены.

theory содержит до 50000 символов. Весь practice-v1 ограничен 256 KiB UTF-8. Обычное число символов не заменяет проверку байтового размера. Передавать заполненные эталоном данные нужно только в редактор наставника; `sanitizePracticeContent` перечисляет публичные поля и удаляет correctIndex, correctAnswer, correctPairs и explanation на всех уровнях, включая бонусы.

## Загрузка отдельными файлами

Существующий комплект сохраняется:

```text
Папка_занятия/
  Урок.md
  questions.json
  images/
    example.png
```

Импорт из папки загружает Markdown и изображения из theory. Файл questions.json можно по-прежнему загрузить отдельной кнопкой импорта заданий. Классический JSON допускает массив вопросов или объект с questions/bonusQuestions. Новый JSON требует полного признака format: practice-v1 и пунктов с variants.

Ссылки `![Пример](images/example.png)` разрешаются относительно Markdown. Загруженные `/media/...` и внешние адреса сохраняются. Обычные заголовки, таблицы GFM, рамки admonition, подсветка и блоки кода сохраняют прежнее поведение. Короткие intro и подписи карточек являются обычным текстом, без отдельного загрузчика изображений.

В импортируемой папке лучше оставлять один Markdown урока. При нескольких файлах действует прежний выбор по числу относительных ссылок на изображения. Архивы полных версий и инструкции храните вне выбираемой папки.

## Необязательная команда внутри Markdown

Чтобы переносить теорию и вопросы одним Markdown, добавьте ровно один ограждённый блок с именем `kvantolingo`. Внутри находится обычный JSON импорта заданий. Команда распознаётся только как отдельный блок Markdown; её упоминание в тексте ничего не меняет.

````markdown
# Пример повторения

Сначала посчитай число повторений.

![Схема](images/example.png)

```kvantolingo
{
  "format": "practice-v1",
  "questions": [
    {
      "id": "repeat-count",
      "intro": "Разберись с количеством повторений.",
      "variants": [
        {
          "id": "first",
          "type": "choice",
          "prompt": "Сколько действий выполнится при двух повторах?",
          "options": ["2", "3"],
          "correctIndex": 0,
          "explanation": "Одно действие в каждом из двух повторов даёт два действия."
        },
        {
          "id": "second",
          "type": "text",
          "prompt": "Сколько действий выполнится при трёх повторах?",
          "correctAnswer": "3",
          "explanation": "В каждом повторе выполняется одно действие, всего три."
        }
      ]
    }
  ],
  "bonusQuestions": []
}
```
````

В этом блоке допустим и классический массив/объект вопросов. Для practice-v1 format обязателен. Не добавляйте параметры после имени команды. Используйте отдельные вопросы либо команду, чтобы не заменять импортированные данные второй копией случайно.

`parseLessonMarkdown` возвращает `{theory, questionImport}`. Команда целиком удаляется из theory до загрузки изображений и показа в редакторе. JSON с правильными ответами не должен отображаться как лекция или попадать в первоначальный payload ученика. Ссылки, случайно присутствующие в тексте вопроса внутри JSON, не загружаются как изображения теории.

Неверный JSON, неизвестная версия, незакрытый или повторный блок дают ошибку до изменения редактора и загрузки изображений. Блок с таким именем внутри более длинного обычного ограждения остаётся примером Markdown и не исполняется. Обычные блоки python/json/других языков не являются командами и остаются в тексте.

Команда является форматом импорта Markdown. В сохранённом JSON она уже должна быть извлечена из theory. Общий парсер отклоняет JSON, где команда осталась в theory, чтобы приватный блок не появился в уроке как лекция.

## Контракты интеграции

- `parseLessonDocument(raw: string)` возвращает классический документ, practice-v1 или null. Проверяйте null до показа и завершения урока.
- `isPracticeContent(document)` различает форматы на границе страницы, редактора и действия.
- `parseLessonQuestionsImport(raw: unknown)` возвращает дискриминированный объект с format: classic или practice-v1 и двумя массивами заданий. classic здесь является внутренним признаком результата, его не требуется записывать в старый Lesson.content.
- `parseLessonMarkdown(raw)` возвращает theory и questionImport либо бросает понятную ошибку. При ошибке текущее содержимое формы сохраняется.
- `importTheoryFolder` сохраняет прежние markdown/missing/done/total; при наличии команды дополнительно возвращает questionImport. Без команды это поле отсутствует.
- `gradePracticeVariant` возвращает invalid для некорректного типа, пустого текста, индекса вне диапазона, неполного или повторного набора пар. В invalid нет эталона и explanation. Только валидная попытка получает checked и разбор.
- `PracticeAttemptInputSchema` ограничивает запрос: lessonId от 1 до 1000000, SHA-256 revision из 64 строчных hex-символов, section core/bonus, itemId, variantId и типизированный answer. Флаг успешности и индекс пункта от клиента не принимаются.

Сначала проверяются доступ и ревизия, затем попытка. Проверка пар и короткого текста выполняется без новых зависимостей, интерпретатора или сетевых вызовов из чистых функций. Прогресс, завершение и монеты остаются ответственностью существующих серверных действий.

## Для выпуска и редакций

Структурные ID, порядок и смысл пунктов связаны с сохранённым прогрессом. Существующий урок с прогрессом нельзя молча превратить в другой формат, поменять местами пункты или заменить их смысл. Новую редакцию такого урока оформляйте отдельным уроком через админку. Ревизия защищает от старой вкладки, но сама по себе не переносит прогресс между редакциями.

Покрытие тестов: старый JSON/Markdown, встроенная команда, неизвестные версии, повреждённый формат, утечка приватных полей, правильные/ошибочные/невалидные ответы, полные пары, переписывание путей изображений и отказ до загрузки при ошибке команды.
