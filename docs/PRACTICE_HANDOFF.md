# Сопровождение practice-v1

## Что готово

Новый формат подключён к Lesson, страницам ученика/предпросмотра, серверной проверке, прогрессу, редактору и импорту JSON/MD. В базе используется существующая строка Lesson.content и существующий UserLessonProgress. Миграция для этого выпуска не требуется. Готовые уроки и картинки не добавлять в репозиторий.

Проверка вариантов и короткого текста сохраняет прежние правила. Новый тип match сравнивает полный набор пар. Старые проверки остаются совместимыми и возвращают boolean; новый сценарий получает результат с разбором. Награда остаётся в completeLesson, не в компонентах упражнения.

## Команде контента

1. Используйте [контракт формата](PRACTICE_FORMAT.md) как источник имён полей, ограничений и синтаксиса команды MD.
2. Старые комплекты MD + images/ + questions.json продолжают работать. Для переноса одним MD можно использовать ровно один блок с языком kvantolingo.
3. В MD основная теория находится вне команды. Решения и explanation находятся внутри JSON команды, а не в тексте ученика. Импорт извлекает команду до показа теории и загрузки картинок.
4. Для Markdown с относительными картинками выбирайте «Импорт из папки». Прямой импорт одного MD не имеет доступа к соседним изображениям и предложит выбрать папку.
5. Обычный MD меняет только теорию и сохраняет вопросы. MD с командой сначала предлагает добавить/заменить задания или отменить операцию. Повреждённая команда не заменяет содержимое формы.
6. Для каждого навыка создавайте 2-3 содержательно разных равноценных варианта. Не делайте два одинаковых вопроса только для прохождения проверки схемы.
7. ID стабильны при повторном экспорте/импорте. Для нового независимого пункта используйте новый ID. Случайный повтор ID отклоняется при добавлении.
8. В новом формате доступны choice, text и match. Python-код пока добавляйте в классический урок. Не выдавайте проверку строки за оценку рассуждения своими словами.
9. Сначала сохраните черновик и проверьте предпросмотр. После публикации или появления прогресса изменённый набор заданий оформляйте отдельным уроком.

Пресеты наград 5 и 20 являются ручными настройками наставника. Повторные попытки и повтор урока не должны создавать дополнительные монеты. Бонусы не являются условием основной награды.

## Команде разработки

Границы модулей описаны в [PRACTICE_CLIENT.md](PRACTICE_CLIENT.md). Схемы, сравнение и безопасная выдача данных находятся в practice-content.ts; различение форматов и MD-команда в lesson-document.ts. Редактор и сервер используют один контракт.

При изменении формата:

- Не удалять discriminator format. Неизвестная версия должна отклоняться, а не распознаваться как classic.
- Не добавлять приватные поля в начальные props страницы ученика. Проверять основной и бонусный наборы.
- Сохранять старые варианты question/text для prompt и старый choice без type в классическом формате.
- Поддерживать roundtrip импорт → редактирование → сохранение → чтение. Проверять ID, explanation, correctPairs, bonusQuestions и MD без изменений.
- Считать завершение по точным индексам answeredCore. Число решений не означает решённый префикс при повторении не по порядку.
- Согласовывать сохранение, проверку revision и запись результата блокировками. Не заменять это локальным Set в одном процессе Node.
- Не менять сумму награды в клиентском запросе. Не добавлять отдельную выплату за разбор или бонус.
- В предпросмотре проверять права наставника на сервере и не записывать ученический прогресс.
- Не писать ответы и исходный код ученика в телеметрию, тестовые снимки рабочего сайта или журналы ошибок.
- Не использовать длинное тире в новом тексте и сообщениях коммитов. Не добавлять трейлеры авторства генератора.

## Минимальная проверка перед выпуском

```powershell
npm test
npm run lint
npx tsc --noEmit
npm run build
```

Unit-тесты не обращаются к БД. Интеграционные/e2e-тесты запускайте только на предназначенной тестовой базе/схеме, не на рабочем подключении. На разработческой машине старое локальное подключение может отличаться от Debian.

Проверьте на тестовой группе:

1. Создание classic с прежним MD/JSON и создание practice-v1 из MD-команды/JSON.
2. Импорт картинок из папки, таблиц, рамок и подсветки. Нет JSON с решениями в ученической теории.
3. Добавление/замену/отмену импорта без потери текущих вопросов; отказ для неизвестной версии, битого JSON и повторов ID.
4. Неверную попытку, разбор, другой вопрос, возврат нового варианта и правильное завершение.
5. Пропущенный пункт не засчитывается через answeredCount. Пустой/повреждённый формат не даёт награду.
6. Потерю сети при проверке и финише. Ввод остаётся, подтверждение можно повторить.
7. Две вкладки и повтор завершения: одна награда. Бонус после финиша не меняет монеты.
8. Предпросмотр наставника не создаёт UserLessonProgress и не меняет баланс.
9. Чужую группу, подменённый ID варианта и устаревшую revision: нет доступа или результата с решением.
10. Изменение опубликованных/начатых вопросов блокируется, метаданные сохраняются.
11. Клавиатуру, касание, узкий экран и изменение ширины с уже созданными связями.
12. Конкурентную проверку/редактирование на настоящем PostgreSQL, затем класс из 30 учеников. Измерять память и ожидание SQL/блокировок, не только скорость сравнения пар.

## Публикация и откат

Сначала выпускается сборка с поддержкой формата, затем создаются новые черновики и пилотные назначения. Сама правка кода не создаёт уроки в базе и не публикует материалы.

Для возврата к сборке, которая не понимает practice-v1, сначала снять новые практики с публикации. Иначе старый парсер может неверно обработать новый контент. Удаление уроков и прогресса не является способом отката.

Работы с инфраструктурой, авторизацией, секретами и действующей базой не входят в это изменение. Связь с «Интересным», автоматическое повторение между днями и перенос кода в новый runner являются отдельными выпусками.
