# Подключение интерактивной практики

Исторический план подключения. Этап Lesson, проверки, прогресса, редактора и MD/JSON-импорта реализован после отдельного задания владельца. Дополнение от 27.10.2026: в рабочих изменениях добавлены code в practice-v1 и вход из «Интересного». Текущее состояние описано в [PRACTICE_CLIENT.md](PRACTICE_CLIENT.md), формат в [PRACTICE_FORMAT.md](PRACTICE_FORMAT.md), сопровождение в [PRACTICE_HANDOFF.md](PRACTICE_HANDOFF.md). Наличие изменений не подтверждает их выпуск на Debian.

Решение для «Интересного» уточнено без миграции: виртуальный тип practice в форме хранится как существующий Resource.type=article с url=`/lesson/id` и coinReward=0. Карточка ведёт в тот же Lesson, а studyResource отклоняет отдельную выплату. Предложенные ниже Resource.lessonId/FK и новый enum не реализованы и не являются инструкцией к следующей миграции. Код practice-v1 использует общий runCode; Python вынесен в Worker с пределами загрузки 45 секунд, выполнения 3 секунды и вывода 10000 символов.

Владелец отдельно поручил внедрение этого плана и совместимость Markdown. Выполнены необходимые изменения серверных действий проверки и прогресса. Авторизация, подключение к БД, инфраструктура, схема Prisma и деплой не изменялись. Дальнейшие пункты ниже сохраняют формулировки первоначального плана.

## 1. Объём первого выпуска

Подключить практику к обычным Lesson: выбор ответа, короткий текст, соединение пар, разбор после попытки и повтор ошибочного пункта в другом варианте. Использовать готовые PracticeRunner, FeedbackPanel и MatchingQuestion.

Существующий классический формат, включая задачи с Python/JavaScript, продолжает работать. Добавление кода в новый PracticeRunner будет отдельным расширением через существующий раннер, без второго интерпретатора. Первый выпуск поддерживает оба направления через вопросы на предсказание, короткий ответ и сопоставление; полнофункциональный редактор Scratch в него не входит.

До подключения предусмотреть и основной маршрут, и необязательные бонусы. Бонусы не блокируют финиш и награду. Полная история попыток, интервальное повторение между днями, произвольные графы и LLM-проверка рассуждений в этот выпуск не входят.

## 2. Какие структуры меняются

| Структура | Решение |
| --- | --- |
| `Lesson` в Prisma | На первом этапе без новых колонок; использовать существующий `content` |
| `Lesson.content` | Добавить явно распознаваемый формат `practice-v1`, не переписывая старый JSON |
| Обычный вопрос | Переиспользовать существующие поля choice/text и добавить объяснение |
| Пункт практики | Стабильный `id`, короткая `intro`, 2-3 варианта одного навыка |
| Вопрос match | Две колонки с независимыми ID и приватный набор правильных пар |
| Ответ проверки | Результат, правильный ответ и объяснение вместо одного boolean в новой точке подключения |
| `UserLessonProgress` | Существующие поля; точный список `answeredCore`, без новой таблицы попыток |
| Очередь повторения | На клиенте; в БД сохраняются подтверждённые решения, не координаты и движения |
| `Resource` | Только на отдельном этапе «Интересного»: nullable `lessonId`, FK и индекс |
| `ResourceType` | На том же этапе добавить `practice` |

### Хранимый формат

Закрепить один явный признак: `format: "practice-v1"`. У старых уроков такого поля нет. Не добавлять одновременно несколько дублирующих полей mode/version/presentation.

```ts
type StoredPracticeContent = {
  format: "practice-v1";
  theory: string;
  questions: StoredPracticeItem[];
  bonusQuestions: StoredPracticeItem[];
};

type StoredPracticeItem = {
  id: string;
  intro?: string;
  variants: StoredPracticeVariant[];
};

// У каждого варианта есть id, prompt и explanation.
// choice сохраняет options и correctIndex.
// text сохраняет correctAnswer и существующее сравнение строк.
// match хранит left, right и correctPairs.
```

Для classic сохраняются текущие вопросы без обёртки variants. Форматы различаются на границе парсинга, а не десятками проверок по всему интерфейсу.

Новые ограничения: 1..50 основных пунктов, 0..20 бонусов, 2..3 варианта; match 2..8 пар; ID до 48 символов; intro до 800; explanation до 1000; текст карточки до 160; весь новый JSON до 256 KiB UTF-8. Уникальность ID, полнота эталонных пар и совпадение размеров колонок проверяются на сохранении и импорте одной Zod-схемой.

Формат practice-v1 пока не реализован в парсере и импорте. Нельзя загрузить такой JSON в существующий редактор и считать, что новые поля сохранятся.

### Публичные данные

Существующий `PracticeItem` уже описывает публичную часть. Для страницы ученика построить её явным перечислением полей. До попытки не передавать correctIndex, correctAnswer, correctPairs и explanation. Не использовать spread приватного варианта.

Учительский предпросмотр должен использовать те же компоненты, но проверять ответы без записи ученического прогресса и без наград. Возможность такого режима подтверждается правами наставника на сервере; пользовательский флаг preview сам по себе права не даёт.

## 3. Сохранить текущую проверку и добавить разбор

Существующие `checkAnswer` и `checkTextAnswer` возвращают boolean. Старые вызовы оставить совместимыми. Для практики добавить действие в существующий модуль проверки и вынести общие части в небольшие функции там, где они реально повторяются.

Не создавать отдельную систему пользователей, проверок доступа, прогресса или монет. Сравнение choice остаётся сравнением с correctIndex, text использует `textAnswersMatch`. Для match добавить чистое сравнение полного набора пар.

Запрос новой проверки:

```ts
type PracticeRequest = {
  lessonId: number;
  revision: string;
  section: "core" | "bonus";
  itemId: string;
  variantId: string;
  answer: PracticeAnswer;
};
```

Текущий клиентский `PracticeAttempt` передаёт itemId/variantId/answer. lessonId, revision и section добавляет адаптер конкретного урока. Так компоненты не зависят от роутинга и Prisma.

Порядок действия: существующий requireUser → canAccessLesson → строгий разбор контента и запроса → проверка revision → поиск пункта и варианта → сравнение ответа → запись прогресса → возврат разбора. Номер пункта для `answeredCore` сервер находит сам, не доверяя клиентскому индексу.

Возврат совместим с уже созданным `PracticeCheckResult`: checked с correct/feedback, invalid или content-changed. Права доступа и сбой БД являются ошибкой запроса, не учебной ошибкой. Разбор возвращается только после валидной попытки текущего варианта. Для match проверять неизвестные ID, повторы и неполный набор, а не только количество пар.

Для сети использовать возможности существующих Server Actions. AbortSignal остаётся локальным контрактом клиента и не сериализуется аргументом серверной функции. При невозможности отменить уже отправленный action адаптер отбрасывает его результат после отмены; серверная запись всё равно должна быть безопасной.

Ответ и explanation намеренно становятся доступны после попытки. Это учебный режим, не защита экзамена от списывания.

## 4. Прогресс и финиш

Для practice-v1:

- `answeredCore` содержит точные индексы успешно решённых основных пунктов. Любой верно решённый равноценный вариант закрывает свой пункт.
- `answeredCount` равен числу уникальных решений и не означает «всё до этого индекса решено».
- Просмотр объяснения и переход после ошибки не меняют answeredCore.
- Resume строит нерешённые ID по отсутствующим индексам. Очередь и выбранный вариант могут отличаться после перезагрузки; это ограничение первого выпуска без новых полей прогресса.
- Завершение проверяет каждый обязательный индекс. Старый fallback из answeredCount сохраняется только для classic.
- Повреждённый новый формат и пустой основной маршрут не позволяют начислить награду. Не использовать текущий fallback к пустым questions для practice-v1 и неизвестных форматов.
- Бонусы имеют отдельную section и не пополняют answeredCore. Завершение основной части достаточно для основной награды.
- Использовать существующий completeLesson, блокировку баланса и защиту первого прохождения. Клиентский finished не является основанием для выплаты.

Странице практики добавить явное событие окончания основной очереди, подтверждение completeLesson, обработку ошибки финиша и предложение бонусов. Защитить двойной запрос/повторные тосты; не запускать выплату как побочный эффект произвольного монтирования компонента. После ошибки финиша ученик повторяет подтверждение, а не весь урок.

Контент с индексным прогрессом нельзя свободно переставлять. Для первого выпуска запретить изменение структуры/смысла опубликованной практики, а также конвертацию classic с существующим прогрессом. После снятия публикации проверка наличия прогресса тоже действует. Новая редакция оформляется отдельным уроком с явным решением о новой награде. Проверку revision и запись результата нужно согласовать с сохранением контента, чтобы устаревший запрос не отметил изменённое задание.

## 5. Порядок подключения и файлы

| Этап | Файлы | Работа |
| --- | --- | --- |
| 1. Контент | `src/lib/lesson-content.ts`, новый небольшой модуль схемы practice при необходимости | Различить classic/practice-v1, проверить формат, построить публичные данные, не маскировать ошибку парсинга |
| 2. Проверка, сервер | `src/lib/actions/gamification.ts`, чистый helper сравнения match | Общая проверка доступа/результата, новый ответ с разбором, совместимость старых boolean-вызовов |
| 3. Прогресс, сервер | `src/lib/lesson-progress.ts`, `src/lib/lesson-resume.ts`, completeLesson | Точное покрытие, восстановление пропусков, прежняя атомарная награда |
| 4. Урок | `src/app/lesson/[id]/page.tsx`, `preview/page.tsx`, компоненты practice | Выбор соответствующего runner на границе формата, адаптер проверки, финиш и бонусы |
| 5. Редактор | `src/app/(main)/admin/lessons/lesson-form.tsx`, отдельный `PracticeEditor` | Выбор формата при создании, редактирование варианта/объяснения, связи между парами, предпросмотр |
| 6. Сохранение, сервер | `src/lib/actions/lessons.ts` | Общая схема, ограничения размера, запрет опасной конвертации/перестановки контента |
| 7. Импорт | Импорт JSON в lesson-form, его выделенный helper при необходимости | Чтение обоих форматов, сохранение variants/explanation/ID без потери полей, понятная ошибка неизвестной версии |
| 8. Остальные потребители | `src/lib/actions/classroom.ts`, `src/lib/classroom-dashboard.ts`, страницы списка/правки admin/lessons | Корректные количества, заголовки пунктов и канонические индексы для новой структуры |
| 9. «Интересное», отдельный выпуск | Prisma, resources, interesting, study | Связать карточку с тем же Lesson и исключить двойную выплату |

В `QuestRunner` не встраивать ещё одну большую машину состояний. Старый runner обслуживает classic, готовый PracticeRunner обслуживает practice. Общие элементы и сравнение переиспользуются. Если серверному общему парсеру понадобится union-тип, пройти все его вызовы, включая список уроков наставника и сессионный дашборд.

В клиентских типах удалить временное дублирование только после появления устойчивого общего публичного контракта. Не смешивать приватные поля решения с публичным DTO ради сокращения количества типов.

Существующий импорт из папки продолжает импортировать теорию и изображения. Для коротких intro первого выпуска достаточно текста, без отдельного загрузчика изображений и сложного редактора в каждом вопросе.

## 6. Монеты

Существующий Lesson.coinReward уже допускает 20. Для первого пилота использовать ручное значение и затем пресеты редактора: короткая проверка 5, полноценный интерактив 20. Эти значения не зависят от страницы входа, ошибок и числа повторов. Массово награды старых уроков не менять. Бонусы не дают дополнительной выплаты в первом выпуске.

Перенастройка суммы в админке и реализация проверки являются разными работами. Не помещать правило выплаты в PracticeRunner.

## 7. Связь с «Интересным»

Этот этап требует небольшой отдельной миграции: ResourceType.practice и Resource.lessonId с FK/индексом. Новых таблиц не требуется. Обратную relation добавить в Lesson. Удаление связанного Lesson ограничить до удаления/отвязки карточки.

Для practice обязательна ссылка на Lesson, Resource.coinReward равен 0, на карточке показывается награда Lesson. Данные вопросов не копируются в Resource.body. Кнопка открывает `/lesson/{id}`.

В `studyResource` на сервере запретить выдачу монет за practice и за любую связанную с Lesson карточку. Прогресс читать из UserLessonProgress одной выборкой для всех карточек, не отдельным запросом на каждую. Доступ определяется существующими назначениями Resource и Lesson/Category; несогласованные назначения проверять при сохранении.

Файлы: `prisma/schema.prisma`, одна миграция, `src/lib/resource-input.ts`, `src/lib/actions/resources.ts`, `src/lib/actions/study.ts`, `src/app/(main)/admin/resources/resource-form.tsx`, `src/app/(main)/interesting/page.tsx`, `card.tsx` и соответствующие тесты.

Открытие одного Lesson из курса и из «Интересного» использует один прогресс и одну награду. Никакой второй функции завершения ресурса.

## 8. Проверки и выпуск

1. Unit: старый/новый/неизвестный формат; обрезанные поля импорта; сравнение text/choice/match; пропуски в answeredCore; очередь вариантов; пустой/повреждённый контент.
2. Интеграционные тесты на отдельной БД: доступ групп, запись подтверждённого решения, завершение с пропусками, две вкладки, первый/повторный финиш, отсутствие выплаты через studyResource, запрет опасного редактирования.
3. Браузер: импорт → сохранение → предпросмотр без ученических записей → прохождение → разбор → повтор → финиш → необязательный бонус. Старые уроки проверить отдельно. Учебный путь работает без «Начать занятие».
4. Производительность: сравнить старые choice и новые match при 30, затем 100 пользователях на тестовом production build. Измерять время проверки, RSS, SQL/ожидание блокировок; не выдавать скорость чистого сравнения пар за скорость сайта. Не отправлять отдельный запрос на открытие разбора или движение линии.
5. Сначала выпустить поддержку формата и проверки с отключённой публикацией практик. Затем создать по одному новому уроку для Scratch и Python в тестовой группе. Только после проверки публиковать реальные материалы через админку.
6. Для отката сначала снять новые практики с публикации, затем возвращать старую сборку: она может не понимать practice-v1. Не обещать безопасный откат только переключением клиентского интерфейса.

Не изменять auth.ts, proxy.ts, server-guard.ts, подключение к БД, deploy/ и scripts/. Существующий heartbeat не оптимизировать вместе с этой функцией; это отдельная задача. Новые зависимости, воркеры для сопоставления и постоянные соединения не требуются.

## Результат первого подключения

Наставник создаёт новую практику и импортирует её вопросы; ребёнок проходит её на реальном маршруте Lesson, получает разбор и возвращается к ошибочным навыкам; сервер подтверждает точные решения и выдаёт существующую награду один раз. Для этого этапа новые таблицы и колонки не нужны.

«Интересное» подключается следующим выпуском с одной дополнительной связью. Подключение Lesson и MD/JSON-импорта реализовано; на рабочем сайте выпуск и публикация ещё не выполнялись.
