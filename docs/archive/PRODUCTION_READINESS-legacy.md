**Главная мысль:** в продакшене это не один навык, а 5–6 разных профессий сразу
(бэкенд, фронтенд, тестировщик, DevOps, безопасник, дизайнер). В командах это разные
люди. Не нужно мастерить всё — нужно знать, что эти слои есть, и закрывать по важности.
Все эти концепции **одинаковы в Python** (pytest, GitHub Actions, Sentry) — изучив их
здесь, знаешь их и для Python.

   стало **6 (0 high, 5 mod, 1 low)**. Обе high закрыты:
   - `npm audit fix` (безопасно) убрал @babel/core, hono, js-yaml, brace-expansion.
   - Next.js вручную поднят **16.2.4 → 16.2.9** (high: DoS/XSS/cache-poisoning). В
     package.json версия была прибита точно, поэтому npm требовал `--force`; сделано
     правкой версии + `npm install`. eslint-config-next тоже → 16.2.9. tsc=0, build зелёный.
   - Связку `prisma/@prisma/dev/@hono/node-server` (3 шт.) добили через npm `overrides`:
     Prisma 7.8.0 жёстко пинит `@prisma/dev@0.24.3` → `@hono/node-server@1.19.11`.
     Добавили `"overrides": { "@hono/node-server": "1.19.14" }` в package.json (заплатка
     в той же ветке 1.19.x, без отката Prisma). 6 → **3**, build остался зелёным.
   - Финальный остаток **3 (0 high, 2 mod, 1 low)** НЕ чиним осознанно: `esbuild`
     (dev-only, приходит из tsx; override на 0.28.x риск сломать tsx) и `postcss`
     (транзитивный ВНУТРИ Next 16.2.9 — уже latest; `--force` тянет next@9.3.3; CSS у нас
     свой, не из пользовательского ввода → реальный риск ≈ 0). Ждут апстрим.
2. ✅ **Автотесты — СДЕЛАНО (2026-06-26).** Поставлен **vitest** (`npm test` → `vitest run`).
   Чистая логика геймификации вынесена из `gamification.ts` (там `"use server"`, нельзя
   экспортировать sync-функции) в отдельный модуль `src/lib/gamification-logic.ts`:
   `calculateLevel`, `fullDaysBetween`, `nextStreak`, `countQuestions`. На неё — 13 тестов
   (`src/lib/gamification-logic.test.ts`): уровни по 100 XP, дни по UTC, правила стрика
   (первый день / тот же день / +1 / сброс при пропуске), парсинг вопросов урока.
   Тесты добавлены в CI отдельным шагом (`.gitea/workflows/ci.yml`: lint → test → build).
   🔻 Server actions целиком (с БД) пока не покрыты — нужен тестовый Postgres; следующий
   слой тестов. Начали с чистой логики — она самая багоопасная и не требует БД.
3. ✅ **CI — СДЕЛАНО (2026-06-24).** Платформа определена: **Gitea** (git.haveaniceday.tech).
   Настроены ДВА слоя проверок:
   - **Серверный (Gitea Actions):** `.gitea/workflows/ci.yml` — при push в main / в PR
     гоняет `npm ci` → `prisma generate` → `lint` → `build`. БД для сборки не нужна
     (роуты динамические), даём фейковые env прямо в workflow. ⚠️ Требует включённых
     Actions + раннер с меткой `ubuntu-latest` на инстансе — если job не стартует,
     проверить раннер (Settings → Actions → Runners в Gitea).
   - **Локальный (git pre-push hook):** `.githooks/pre-push` — перед каждым push гоняет
     быстрые `lint` + `tsc --noEmit` (полную сборку оставили серверу). Подключается раз:
     `git config core.hooksPath .githooks` (это ЛОКАЛЬНАЯ настройка, не коммитится — на
     новой машине повторить). Разовый обход: `git push --no-verify`.
   - ✅ Тесты в CI гоняются (шаг «Тесты (vitest)» между линтером и сборкой) — см. п.2.
4. ✅ **Мониторинг ошибок — СДЕЛАНО локально (2026-06-26).** DSN получен, прописан в `.env`,
   живая проверка прошла (тестовая ошибка доставлена, flush ok, eventId выдан). 🔻 Осталось
   на прод: добавить `NEXT_PUBLIC_SENTRY_DSN` в Vercel env (Production). Подключён `@sentry/nextjs`
   (10.62.0; поддерживает Next 16). Минимальный вариант — только отлов ошибок, без билд-
   плагина `withSentryConfig` (он нужен для source maps + auth-токен — отдельный шаг «потом»).
   Файлы по конвенциям Next 16: `src/instrumentation-client.ts` (браузер, init + хук
   навигации `onRouterTransitionStart`), `src/instrumentation.ts` (сервер: `register()` init
   + нативный `onRequestError = captureRequestError`). Всё завязано на `NEXT_PUBLIC_SENTRY_DSN`:
   нет ключа → выключено (init не вызывается, ничего не шлётся). `tracesSampleRate: 0` —
   только ошибки, без трейсинга (бережём бесплатный тариф). tsc/lint/build/тесты зелёные.
   🔻 **Осталось (нужен аккаунт пользователя):** завести проект на sentry.io → получить DSN →
   положить в `.env` (локально) и в Vercel env (прод) как `NEXT_PUBLIC_SENTRY_DSN` → проверить
   живой ошибкой. source maps (читаемые стектрейсы) — позже через `withSentryConfig` + токен.
5. ⏳ **Заголовки безопасности — ЧАСТИЧНО (2026-06-24).** В `next.config.ts` через
   `async headers()` (source `/(.*)`) добавлены 6 «непробиваемых» заголовков:
   HSTS (`max-age=63072000; includeSubDomains`), X-Frame-Options (SAMEORIGIN),
   X-Content-Type-Options (nosniff), Referrer-Policy (strict-origin-when-cross-origin),
   Permissions-Policy (camera/mic/geo/topics выключены), X-DNS-Prefetch-Control (on).
   Проверено на проде-сборке локально (`next start` → curl -I: все 6 присутствуют, сайт 200).
   🔻 **CSP пока НЕ добавлен** — сознательно: для App Router нужен nonce + правка
   middleware, кривой CSP блокирует inline-скрипты Next и кладёт страницы. Отдельный
   аккуратный шаг с тестами (можно начать с Content-Security-Policy-Report-Only).
6. ✅ **Долг по миграциям БД — СДЕЛАНО (2026-06-30).** Сделан ре-baseline: живая БД
   совпадала со схемой (`migrate diff` пуст), но история врала (3 записи в
   `_prisma_migrations`, включая `add_wrong_attempts` без локального файла; 2 локальных
   файла создавали уже удалённый инвентарь). Свернул всё в одну `0_init` (через
   `migrate diff --from-empty --to-schema`), очистил служебную таблицу `_prisma_migrations`
   (бэкап снят, реальные данные не тронуты) и пометил `0_init` применённой
   (`migrate resolve --applied`). Итог: `migrate status` = «up to date» (1 миграция),
   `diff` пуст. Теперь `migrate dev` для новых таблиц не потребует reset.
