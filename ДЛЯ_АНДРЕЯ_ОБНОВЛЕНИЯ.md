# Андрею: как подключить автоматические обновления

Основной исходный код — GitHub: `leonidzaharov/Kvantol1nGo`. Разработчик
отправляет изменения в `main`. GitHub Actions проверяет их и только после
успеха переводит `production` на новый коммит. **Рабочий Debian должен читать
только `production` из GitHub.** Gitea (`Sunless4ik/KVANTOLINGO`, ветка `test`)
служит черновиком и не обновляет рабочий сайт.

Подробные файлы в репозитории:

- `docs/DEBIAN_SETUP.md` — первый запуск приложения, PostgreSQL и uploads;
- `deploy/linux/AUTO-DEPLOY.md` — пошаговая настройка GitHub deploy key,
  systemd-службы и таймера;
- `deploy/linux/quantorium-deploy.mjs` — сама установка новой версии;
- `deploy/linux/quantorium-deploy.service` и `quantorium-deploy.timer` —
  запуск проверки обновлений примерно раз в минуту;
- `deploy/linux/quantorium.service` — работа сайта.

Если сайт уже установлен, **сначала сверить** реальные пути, пользователя
службы, `/etc/quantorium.env`, порт и PostgreSQL с инструкцией. Не клонировать
репозиторий поверх работающего каталога и не восстанавливать базу повторно.
Перед включением таймера проверить сайт и базу через `/api/health`. Затем
настроить чтение GitHub с отдельным deploy key **без права записи** и выполнить
первое обновление вручную по `deploy/linux/AUTO-DEPLOY.md`. Публичную часть
ключа владелец репозитория добавляет в GitHub → Settings → Deploy keys;
закрытую часть не пересылают.

После успешного ручного обновления включить таймер и проверить его:

```sh
sudo systemctl enable --now quantorium-deploy.timer
systemctl list-timers quantorium-deploy.timer --no-pager
sudo journalctl -u quantorium-deploy.service -n 100 --no-pager
curl -fsS https://it-quan.kpcollege.ru/api/health
```

Скрипт обновления скачивает `production`, собирает приложение, **перед миграцией
делает копию базы PostgreSQL и uploads**, применяет Prisma-миграции,
перезапускает службу и проверяет здоровье. Код хранится в Git; база, загруженные
картинки и секреты — отдельно на сервере. Не помещать пароли и `.env` в GitHub,
Gitea или переписку. Файлы самой службы и таймера обновляются отдельно,
как описано в конце `deploy/linux/AUTO-DEPLOY.md`.

Обычный порядок для Леонида: изменить код → коммит → `git push origin main` →
дождаться зелёного **CI** на GitHub. После этого GitHub обновит `production`,
а настроенный таймер Debian заберёт релиз. Если CI красный, `production` и сайт
не меняются. Материалы уроков и профили учеников редактируются через админку:
для этого Git не нужен.
