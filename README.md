# KvantoL1nGo

Учебная платформа Кванториума: уроки, задания в браузере, группы, прогресс,
достижения и кабинет наставника.

## Что находится в репозитории

| Каталог | Назначение |
| --- | --- |
| `src/app` | Страницы ученика и наставника, API и оформление |
| `src/lib` | Правила доступа, учебная логика, работа с данными |
| `prisma/schema.prisma` | Модель PostgreSQL |
| `prisma/migrations` | Изменения структуры базы |
| `public` | Встроенные изображения и аватары |
| `scripts` | Служебные команды, резервирование и восстановление |
| `deploy/linux` | Настройки Debian, systemd и обновления |
| `docs` | Архитектура и материалы по переносу |

Приложение написано на TypeScript, Next.js 16 и React 19. База данных —
PostgreSQL через Prisma 7. Вход учеников и наставника работает через Auth.js;
PIN хранится в виде bcrypt-хеша. Загруженные через редактор картинки в локальном
режиме лежат в отдельной папке сервера.

Исходники **не содержат** рабочую базу, загруженные пользователями файлы,
пароли или `.env`. Для переноса данных нужен отдельный архив. Порядок
установки описан в [инструкции для Debian](docs/DEBIAN_SETUP.md). Папка
`lectures` в репозиторий не входит.

## Запуск для разработки

Нужны Node.js 24, npm и отдельная база PostgreSQL. Скопируйте необходимые
настройки в `.env.local`, используя
[`deploy/linux/environment.example`](deploy/linux/environment.example) как
образец. Укажите адрес **своей локальной** базы, `AUTH_SECRET`, локальный
`AUTH_URL`, `STORAGE_DRIVER=local` и `UPLOADS_DIR`. Рабочие секреты не
коммитьте.

```sh
npm ci
npx prisma generate
npx prisma migrate deploy
npm run dev
```

Основные проверки:

```sh
npm run lint
npm test
npx tsc --noEmit
npm run build
```

Интеграционные тесты требуют отдельной тестовой схемы PostgreSQL. Полный набор
проверок выполняет `npm run verify:ci` в GitHub Actions.

## Как выпускать изменения

1. Меняйте код в `main` и отправляйте его в GitHub: `git push origin main`.
2. Дождитесь успешного workflow **CI** на GitHub. Он обновит `production`.
3. После настройки по
   [инструкции автоматического обновления](deploy/linux/AUTO-DEPLOY.md)
   Debian заберёт `production`, сохранит резервные копии и перезапустит сайт.

Для отдельной проверки в Gitea: `git push gitea main:test`. Это не заменяет
GitHub CI и не запускает обновление Debian.

Текущие данные приложения и картинки находятся на сервере отдельно от Git.
Изменение кода не заменяет эти данные. Перед первичной установкой
администратору нужен отдельный архив с актуальной копией базы и загруженных
изображений.
